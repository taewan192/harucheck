# 하루체크 · 2026–2027

하루 일정을 추가·수정·삭제하고, ✓ 완료 또는 ✕ 실패로 기록하는 한국어 캘린더 웹앱입니다. HTML·CSS·JavaScript로 만들었으며 서버 데이터베이스나 회원가입이 필요하지 않습니다.

이 저장소는 앱과 디자인의 수정 원본을 보관합니다. GitHub에 소스를 올리는 것만으로 웹사이트가 배포되거나 사용자의 일정이 동기화되지는 않습니다.

## 현재 기능

- 2026년 1월부터 2027년 12월까지 월별 달력, 날짜별 일정 관리
- 설정에서 화이트·다크 모드 및 10개 언어 선택·저장
- 달력에 일정 제목 라벨을 시간순으로 표시, 여러 일정은 세로로 쌓기
- 예정·완료·실패 상태 및 날짜별 진행률
- 일정 시작 시점 또는 30분~5시간 전 알림을 30분 간격으로 선택
- 필수 알림 권한 흐름과 원하는 날짜·시간의 맞춤 알림
- 일정별 소리·진동, 기기의 소리 파일 가져오기와 브라우저 내부 저장
- 저장한 일정 하나를 `.ics` 파일로 내보내기

화면 사용법과 알림 조건은 [사용안내](docs/사용안내.md)에 정리했습니다.

## 바로 열기

빌드된 `harucheck.html`에는 스타일과 앱 코드가 포함되어 있습니다. 이 버전은 알림 권한을 필수로 요구하므로 아래 로컬 서버 또는 HTTPS 환경에서 실행해야 합니다. `file:`로 직접 열거나 알림을 지원하지 않는 환경에서는 일정 화면이 잠깁니다.

## 개발 환경에서 실행

Node.js 20 이상이 필요합니다. 앱 실행에는 외부 npm 의존성이 없어 설치가 필요하지 않습니다. 자동 검사를 실행하려면 개발 의존성을 `npm ci`로 설치합니다. 비공개 저장소를 복제하려면 접근 권한이 있는 계정으로 Git 인증을 설정해야 합니다.

```sh
git clone https://github.com/taewan192/harucheck.git
cd harucheck
node scripts/start.mjs
```

앱을 빌드한 뒤 서버가 시작됩니다. 브라우저에서 `http://127.0.0.1:5173/harucheck.html`을 엽니다. 서버 종료는 터미널에서 `Ctrl+C`를 누릅니다. npm도 설치되어 있다면 `npm start`로 같은 작업을 실행할 수 있습니다.

## 수정하고 확인하기

### 모바일 화면

`http://127.0.0.1:5173/mobile-preview.html`에서 휴대폰 크기로 미리 볼 수 있습니다. 실제 앱은 화면 폭에 따라 자동으로 모바일 레이아웃을 적용합니다.

- 하단 고정 일정 추가 버튼과 모바일 입력 시트
- 달력 제목은 한 줄로 표시하며, 날짜당 2개를 넘는 일정은 `+N개`로 표시
- 선택한 날짜 아래에서는 모든 일정과 전체 제목을 확인
- 320px 소형 화면, 화면 하단 안전 영역, 화이트·다크 모드 지원

편집 가능한 [Figma 모바일 디자인](https://www.figma.com/design/cVxZtXs7GbK237jxdrnpR1?node-id=2-60)에는 화이트 캘린더, 다크 캘린더, 일정 추가 화면이 포함되어 있습니다.

`src/`의 원본을 수정한 뒤 다음 명령을 실행하고 브라우저를 새로고침합니다.

```sh
npm ci
node scripts/build.mjs
node scripts/build.mjs --check
node --test
```

npm을 사용하는 경우 `npm run build` 후 `npm test`를 실행하면 됩니다. `npm test`는 빌드 결과가 원본과 일치하는지 확인한 뒤 테스트를 실행합니다.

빌드하면 최상위 `harucheck.html`과 `harucheck-sw.js`가 다시 생성됩니다. 두 결과물을 직접 수정하면 다음 빌드에서 덮어쓰므로 원본을 수정해주세요. 변경을 GitHub에 저장할 때는 원본과 갱신된 빌드 결과를 함께 커밋합니다.

자동 검사는 알림 시간 계산·중복 처리·캘린더 내보내기, 10개 언어의 번역, 권한 게이트, 소리 파일의 저장·재실행·실패·충돌 처리와 빌드 결과를 검사합니다. 브라우저 권한, 모바일 화면 및 OS 알림 전달은 별도 실행 환경에서 확인해야 합니다.

| 경로 | 수정 대상 |
| --- | --- |
| `src/template.html` | 화면 구조, 입력 항목과 문구. `@@파일명@@`은 빌드 삽입 위치 |
| `src/styles.css` | 색상, 테마, 라벨, 모바일 레이아웃 |
| `src/theme-init.js` | 첫 화면에 저장된 테마 적용 |
| `src/app.js` | 달력 렌더링, 일정 CRUD, 저장, 알림 화면·실행 |
| `src/reminder-core.js` | 알림 계산과 `.ics` 생성 |
| `src/i18n.js` | 10개 언어의 화면 문구 |
| `src/alert-media.js` | 기기 내부 소리 저장, 재생과 진동 |
| `manifest.webmanifest`, `assets/` | 홈 화면 실행 설정과 아이콘 |
| `src/harucheck-sw.js` | 지원 환경에서 시스템 알림 표시·클릭 처리 |
| `scripts/` | 빌드·로컬 서버·디자인 생성 도구 |
| `tests/` | 자동 검사 |
| `design/` | Figma 가져오기용 SVG와 PNG 미리보기 |

## 디자인 수정

`design/harucheck-figma.svg`를 Figma 캔버스에 끌어 넣으면 화이트 달력, 다크 달력, 일정 추가, 일정 수정의 4개 화면을 가져올 수 있습니다. SVG는 벡터·텍스트 기반의 정적 보드이며 앱의 기능과 데이터를 포함하지 않습니다.

디자인 생성 원본은 `scripts/make_figma_board.py`입니다. Python 3이 설치된 환경에서 다음 명령으로 SVG를 다시 만듭니다.

```sh
python scripts/make_figma_board.py
```

환경에 따라 `python` 대신 `python3`를 사용합니다. npm과 `python` 명령이 있다면 `npm run design:svg`로도 실행할 수 있습니다. PNG는 미리보기 이미지입니다. 위 명령은 SVG만 생성하므로 디자인이 바뀌면 PNG도 별도로 다시 내보내주세요. Figma에서 수정한 내용과 웹앱 소스는 자동으로 동기화되지 않습니다.

## 저장 방식과 범위

일정과 환경설정은 현재 브라우저의 `localStorage`, 소리 파일은 `IndexedDB`에 저장됩니다. 실제 사용자가 입력한 일정은 이 저장소에 포함되지 않으며 GitHub로 업로드되지 않습니다. 브라우저 데이터 삭제 시 사라질 수 있고, 다른 브라우저·기기·주소에서는 별도의 저장 공간을 사용합니다. 예를 들어 파일 직접 열기, `localhost`, `127.0.0.1`로 열기는 동일한 일정을 공유하지 않습니다.

알림은 **앱이 실행 중일 때** 시간을 확인합니다. 종료·절전·백그라운드 제한 상태에서는 정시 알림을 보장하지 않습니다. 알림 권한은 필수이며 지원하지 않는 환경에서는 앱을 사용할 수 없습니다. 시스템 알림음은 기기 알림 설정을 따르고, 개인 소리 재생과 웹 진동은 지원 기기에서 앱이 열린 동안 제공됩니다. 휴대폰 기본 알람음 직접 연동은 제공하지 않습니다. 서비스 워커는 앱이 닫힌 상태의 예약 알림이나 서버 푸시를 구현하지 않습니다. `.ics` 내보내기는 복사본이며 가져온 캘린더에서 알림을 확인해야 합니다.

지원 날짜 범위는 2026–2027년으로 고정되어 있습니다. 범위를 늘릴 때는 앱의 날짜 검증·월 이동, HTML 입력 제한·연도 선택·표시 문구, 관련 디자인을 함께 수정해야 합니다. 계정·클라우드 동기화·반복 일정·백그라운드 예약 알림·전체 일정 백업/복원·네이티브 앱 패키징은 구현되어 있지 않습니다. 재도전, 준비·출발 알림, 마감 관리 등 추가 아이디어도 현재 기능에는 포함되지 않습니다.
